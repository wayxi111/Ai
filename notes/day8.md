## 知识主线（今天真正学会的东西）

1. **`dense_backward` 接口大修：从吃 t 改为吃 dy**
   - 旧版内部 `dy = y - t` 只对贴着 loss 的层合法。两层串联时把 `dx2` 当 `t` 喂入，函数算出 `h1 - dx2` 而不是 `dx2`——责任流在层1门口被篡改
   - 新分工：**调用侧算 dy**（输出层 `dy = y-t`，中间层 `dy = 上一层的 dx`），**函数只管卸货+转发**。损失函数的求导属于 loss 层，不属于 dense 层
   - Day 7 "零修改复用"当时没跑梯度检验，错误潜伏到今天才被审计员抓住。教训：**改完接口必须重新对拍，哪怕"看起来还是那一套"**

2. **sum loss vs mean loss：/B 只写在一个字符串里**
   - `L = 0.5·Σ(y-t)²/B`——除 B 写在 loss 定义那一行。对 y 求导时 /B 是外层常数自动带出：`dy=(y-t)/B`
   - 之后 1/B 长在 dy 身上，随责任流流遍全网，dW/db 天然拿到"平均"而不是"求和"→ 梯度量级不随 batch size 翻倍，lr 保持稳定
   - 若 loss 除一次、dy 再手除一次 = 除 B²，梯度缩小 B 倍；且对拍不会报警（解析/数值用同一个 loss，错得一致）→ **对拍抓不住"两次抵消"型 bug，只能靠量纲检查**

3. **batch 化：参数 vs 数据的身份不对称**

   | | W, b（参数） | x（数据） |
   |---|---|---|
   | batch 中出现次数 | 64 个样本共用同一份 | 每样本各自一份 |
   | 梯度形状 | `(D_in,D_out)`/`(D_out,)` 无 batch 维 | `(B,D_in)` 带 batch 维 |
   | 责任怎么算 | `dW = x.T @ dy`（64 个外积求和）；`db = dy.sum(0)` | `dx = dy @ W.T`（各行各自转发）|
   | 前向何时生效 | x@W 时作用于每个样本 | 同左（一行一样本）|

4. **ReLU 门的位置：层1 与层2 之间，前向存 h**
   - 反向 `dh = da·(h>0)`：只用 ReLU 的开关信息，不用它的数值；h≤0 的门口责任掐死，h>0 原样放行
   - 它是链式法则对"逐元素函数"的特例：`a=f(h)` 逐元素 → `dh = f'(h)⊙da`，此处 f' = (h>0)
   - 图：前向 `x→h→a→y`（h、a 都存档），反向 `dy→da→过门→dh→dx`
5. **优化器初体验（四层直觉第 4 层兑现）**
   - 裸 SGD 需要大 lr + 多 epoch（0.18/24ep）；动量版（mom=0.9）5ep 达标
   - 电气暗道：动量 = 储能元件（速度状态不立即归零），`v ← 0.9v − lr·∇`，平坦区滑得快、锯齿谷振得小
   - 自检技巧：初速 0 时第一步数学上等于 SGD，第一步 loss 应与 SGD 版完全一致，之后才分岔

## 卡点金矿（按踩坑顺序，全部记档）

> 卡点一（`dy` 接口回归）：重写两层 cell 时把 Day 7 已修对的 `dense_backward(x,W1,b1,dx2)` 退回成喂 `t`——旧上下文残留污染。教训：**接口刚改完的窗口期最容易回写旧模式，改接口时把所有调用处列清单逐个过**
> 卡点二（`return dx, dW, db` 大小写笔误）：函数体内算的是 `dw`（小写），return 却引用 `dW`——Python 从全局捞到别的 cell 遗留值，**不报错、返回无关矩阵**。防御：return 里每个名字必须在函数体内赋值过；笔误会静默选全局。这是作用域家族第 3 案（前两案：Day 7 `y` 死代码、`y-t` 该在调用侧）
> 卡点三（`np.outer` 拍平）：batch 版误用 `np.outer(x, dy)`——它把 (8,5) 和 (8,3) 拉平成 40 维 × 24 维大外积，样本边界消失。矩阵乘法天生是"配对+求和"机器：`x.T @ dy` = 8 个外积的逐元素累加。**单样本的外积到了 batch 要换成 x.T @**
> 卡点四（`rng.normal(0, (128,))` 参数槽笔误）：形状写进了 scale 槽，`(128,)` 被广播成标量 1，`b1` 变成形状 ()。静默错误，直到 `b1 -= lr·db1` 广播失败才炸。防御：初始化后打印 `.shape`；数值库对错误形状参数的宽容是固定踩坑主题
> 卡点五（`relu` 用了 Python `max`）：`max(0,a)` 对数组报 truth value 歧义——逐元素语义必须 `np.maximum`。和 Day 5 `np.cos` 教训同族：**Python 内建的是"整个数组一个答案"，NumPy 的才是"逐元素各自回答"**
> 卡点六（监控函数与训练失同步）：打印 loss 用的 `L_total` 是任务 1 的两层无 ReLU 版，训练加了门、监控没跟上 → 打印的是幽灵路径的 loss（乱跳上扬），而真实训练其实正常单掉。教训升级：**监控指标和训练目标必须是同一个函数的两份引用，不是两个相似函数**——单一可信源，重复定义必失同步
> 卡点七（半成品下载被 exists 判定合格）：网络中断留下残缺 .gz，文件名在 → `os.path.exists` 放行 → gzip 读到一半 EOFError。修法三件套：**.part 临时名 + 字节数 assert（SIZES 表）+ 原子 rename**。校验逻辑真的拦东西（我把期望值写错时它当场拦了我）
> 卡点八（监控打印 `if num > 100`）：条件无出口，每批都打，937 行/epoch 刷屏。应为 `num % 100 == 0`
> 实验注（eps 量级匹配）：任务1权重下 L≈6452，eps=1e-6 时对拍卡在 1e-6~1e-7 边缘（浮点噪声）；eps=1e-4 → 误差 1e-9。**loss 量级大，eps 要相应放大**。与 Day 4 的 1e-16 教训同族：浮点相对误差跟着量级走

## 代码骨架（最终在跑的版本）

```python
def dense_backward_batch(x, W, dy):
    dW = x.T @ dy          # 64个外积求和
    db = dy.sum(axis=0)    # 沿样本轴汇总
    dx = dy @ W.T          # 各样本各自转发
    return dx, dW, db

# 训练循环核心（动量版）
for tx, tb in make_batches(X_train, T_train):     # permutation打乱行号→顺序切片，无重复无遗漏
    h  = dense_forward(tx, W1, b1)     # 存档！ReLU门要用 h 判 >0
    a  = relu(h)
    y  = dense_forward(a, W2, b2)
    dy = (y - tb) / tx.shape[0]        # 唯一一次除B；贴loss层的求导
    dx2, dW2, db2 = dense_backward_batch(a, W2, dy)
    dh = dx2 * (h > 0)                 # 过门：负h门口责任掐死
    dx1, dW1, db1 = dense_backward_batch(tx, W1, dh)
    vW1 = mom*vW1 - lr*dW1;  W1 += vW1 # 动量：速度状态（初值 zeros_like）
```
